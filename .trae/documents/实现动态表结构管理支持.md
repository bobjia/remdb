# 实现动态表结构管理支持

## 1. 问题分析
当前表结构管理存在以下限制：
- 表定义(TableDef)是静态的，一旦创建无法修改
- 字段名使用`Box::leak`转换为静态字符串，无法动态释放
- 不支持`ALTER TABLE`语法和动态字段修改
- 表结构在创建时固定，不支持添加/修改/删除字段

## 2. 实现计划

### 2.1 修改核心数据结构
- 修改`TableDef`和`FieldDef`结构，支持动态字段管理
- 将静态字符串改为使用`Arc<str>`或`String`来支持动态内存管理
- 为`TableDef`添加版本号，支持表结构变更跟踪

### 2.2 实现ALTER TABLE语法支持
- 在`sql/query_parser.rs`中添加`ALTER TABLE`语法解析
- 支持以下操作：
  - `ADD COLUMN`：添加新字段
  - `DROP COLUMN`：删除现有字段
  - `MODIFY COLUMN`：修改字段类型/约束
  - `RENAME COLUMN`：重名字段

### 2.3 实现表结构动态修改逻辑
- 在`lib.rs`的`DdlExecutor` trait中添加`alter_table`方法
- 实现表结构变更的核心逻辑：
  - 计算新的记录大小和字段偏移量
  - 分配新的内存空间
  - 迁移现有数据到新结构
  - 更新索引和约束
  - 确保事务一致性

### 2.4 实现内存管理优化
- 改进字段名的内存管理，避免内存泄漏
- 实现表结构变更时的内存重分配和数据迁移
- 确保修改过程中的数据完整性

### 2.5 测试和验证
- 添加`ALTER TABLE`相关的单元测试
- 测试各种表结构变更操作
- 验证数据一致性和完整性
- 测试并发场景下的表结构变更

## 3. 关键技术点

### 3.1 字段偏移量重新计算
- 当添加或删除字段时，需要重新计算所有字段的偏移量
- 确保数据迁移时字段值被正确复制到新位置

### 3.2 数据迁移策略
- 实现高效的数据迁移算法，减少性能影响
- 支持在线迁移，避免长时间锁定表

### 3.3 事务一致性
- 确保表结构变更在事务中是原子操作
- 支持回滚机制，避免部分失败导致的数据不一致

### 3.4 索引更新
- 当字段类型或名称变更时，更新相关索引
- 确保索引与表结构保持一致

## 4. 预期结果
- 支持完整的`ALTER TABLE`语法
- 能够动态添加、修改和删除字段
- 保持数据一致性和完整性
- 支持事务性的表结构变更
- 优化内存使用，避免内存泄漏

## 5. 实现步骤
1. 修改`types.rs`中的`TableDef`和`FieldDef`结构
2. 实现`ALTER TABLE`语法解析
3. 实现表结构变更的核心逻辑
4. 优化内存管理
5. 添加测试用例
6. 验证功能正确性和性能

通过以上实现，将使RemDB支持动态表结构管理，增强数据库的灵活性和扩展性，满足更多实际应用场景的需求。
