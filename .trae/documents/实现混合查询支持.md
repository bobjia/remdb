# 实现混合查询支持

## 问题分析
当前的SQL查询实现中，当在WHERE子句中遇到向量距离表达式（如`<->`、`<#>`、`<=>`）时，只是简单返回true，而没有实际执行距离计算和比较。这导致向量条件没有被正确过滤，无法与结构化查询条件（如`category = 'electronics'`）正确组合使用。

## 实现目标
支持在同一个WHERE子句中同时使用结构化查询条件和向量查询条件，例如：
```sql
SELECT * FROM products WHERE category = 'electronics' AND vector <-> [1.0, 2.0, 3.0] < 0.5
```

## 实现步骤

### 1. 实现向量距离计算函数
- 在`query_executor.rs`中添加向量距离计算函数，支持L2距离（`<->`）、内积（`<#>`）和余弦相似度（`<=>`）
- 函数应接收两个向量作为输入，返回距离值

### 2. 修改条件评估函数
- 修改`evaluate_comparison`和`evaluate_comparison_with_alias`函数，使其能够正确处理向量距离表达式
- 当检测到向量距离表达式时，解析表达式，提取向量字段名和比较向量
- 计算实际距离值，并与条件中的阈值进行比较
- 返回比较结果

### 3. 支持BETWEEN条件中的向量距离
- 修改`evaluate_between`和`evaluate_between_with_alias`函数，使其能够正确处理向量距离表达式
- 实现类似的距离计算和比较逻辑

### 4. 确保逻辑操作符正确处理
- 确保AND/OR逻辑操作符能够正确组合结构化条件和向量条件
- 不需要修改现有逻辑，因为它们已经递归调用条件评估函数

### 5. 添加测试用例
- 在`tests/sql_query_test.rs`中添加混合查询测试用例
- 测试不同组合的结构化条件和向量条件
- 测试不同的向量距离操作符

## 预期效果
- 支持在同一个WHERE子句中同时使用结构化查询条件和向量查询条件
- 向量距离表达式能够正确计算和比较
- AND/OR逻辑操作符能够正确组合不同类型的条件
- 查询结果符合预期

## 代码修改范围
- `src/sql/query_executor.rs`：实现向量距离计算和修改条件评估函数
- `tests/sql_query_test.rs`：添加混合查询测试用例
