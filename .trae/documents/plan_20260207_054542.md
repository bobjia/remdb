# 测试用例整理计划

## 发现的重复内容

### 1. TestPlatform 结构体重复（34个文件）
几乎所有测试文件都包含相同的 `TestPlatform` 实现，包括：
- `database_test.rs`
- `table_test.rs`
- `sql_query_test.rs`
- `sql_transaction_test.rs`
- `transaction_test.rs`
- `sql_boolean_ops_test.rs`
- `sql_real_ops_test.rs`
- `sql_insert_ignore_test.rs`
- `vector_test.rs`
- `vector_operators_test.rs`
- `vector_operators_functions_test.rs`
- `vector_operators_data_types_test.rs`
- 等30+个文件

### 2. 数据库初始化代码重复
每个测试文件都包含相同的初始化模式：
- `init_platform(&TEST_PLATFORM)`
- `init_global_allocator()`
- `reset_global_db()`
- `init_global_db(config)`

### 3. 向量测试文件高度重复
- `vector_test.rs` - 基本向量测试（895行）
- `vector_operators_test.rs` - 向量操作符测试（525行）
- `vector_operators_functions_test.rs` - 向量函数测试（559行）
- `vector_operators_data_types_test.rs` - 向量操作符与数据类型测试（758行）
- 这些文件有大量重复的测试设置、表定义、记录结构

### 4. 事务测试重复
- `transaction_test.rs` - 底层API测试事务（1236行）
- `sql_transaction_test.rs` - SQL语句测试事务（332行）
- 测试相同的功能，只是方式不同

### 5. SQL测试文件部分重复
- `sql_query_test.rs` - 包含大量SQL查询测试（1437行）
- `sql_syntax_test.rs` - SQL语法解析测试（45行）
- `sql_boolean_ops_test.rs` - 布尔操作测试（249行）
- `sql_real_ops_test.rs` - 实数操作测试（200行）
- `sql_insert_ignore_test.rs` - INSERT IGNORE测试（208行）

## 整理方案

### 阶段1：提取公共测试辅助代码
1. 创建 `tests/common/mod.rs` 模块
2. 提取 `TestPlatform` 到 `common/platform.rs`
3. 提取数据库初始化辅助函数到 `common/db_setup.rs`
4. 提取测试内存管理辅助函数

### 阶段2：合并重复的向量测试
1. 合并 `vector_test.rs`、`vector_operators_test.rs`、`vector_operators_functions_test.rs`、`vector_operators_data_types_test.rs` 到 `vector_test.rs`
2. 按功能组织测试用例（基本功能、操作符、函数、数据类型）
3. 移除重复的表定义和记录结构

### 阶段3：合并事务测试
1. 合并 `transaction_test.rs` 和 `sql_transaction_test.rs` 到 `transaction_test.rs`
2. 按测试类型组织（底层API、SQL API）
3. 统一测试设置

### 阶段4：优化SQL测试
1. 保留 `sql_query_test.rs` 作为主要SQL测试文件
2. 将 `sql_syntax_test.rs` 的解析测试合并到 `sql_query_test.rs`
3. 将 `sql_boolean_ops_test.rs`、`sql_real_ops_test.rs`、`sql_insert_ignore_test.rs` 的特定测试合并到 `sql_query_test.rs` 的相应章节
4. 按SQL功能组织（SELECT、INSERT、UPDATE、DELETE、事务等）

### 阶段5：清理和验证
1. 删除已合并的测试文件
2. 更新所有测试文件的导入语句
3. 运行测试确保没有破坏
4. 更新文档（如果有）

## 预期效果
- 减少约 3000+ 行重复代码
- 统一测试风格和结构
- 提高测试可维护性
- 减少测试文件数量约 10-15 个
