# 增量快照功能实现计划

## 1. 核心思路

增量快照功能只保存自上次快照以来发生变化的记录，通过记录版本号跟踪变化。

## 2. 实现步骤

### 2.1 数据结构扩展

* **修改** **`RemDb`** **结构体**：添加全局快照版本号，用于跟踪上次完整快照的版本

* **修改** **`MemoryTable`** **结构体**：添加表级快照版本号，用于跟踪上次快照时该表的版本

### 2.2 快照文件格式扩展

* 扩展现有快照格式，添加增量快照标记

* 增量快照包含：

  * 快照类型（完整/增量）

  * 基础版本号（基于哪个完整快照）

  * 仅包含版本号大于表快照版本的记录

### 2.3 核心方法实现

* **`save_snapshot`** **方法**：保存完整快照时，更新全局和表级快照版本号

* **`save_incremental_snapshot`** **方法**：新增方法，只保存版本号变化的记录

* **`restore_snapshot`** **方法**：扩展支持从增量快照恢复，合并变化记录

### 2.4 记录版本管理

* 确保所有数据修改操作（插入、更新、删除）都会增加记录的版本号

* 快照版本号与记录版本号关联，用于识别变化

### 2.5 测试用例

* 更新现有快照测试，验证增量快照功能

* 添加新的测试用例，验证：

  * 增量快照只包含变化的记录

  * 从增量快照恢复数据的正确性

  * 多次增量快照的合并

## 3. 实现细节

### 3.1 快照文件格式

```
[魔数(4B)][版本(4B)][快照类型(1B)][基础版本(4B)][表数量(4B)][表1数据][表2数据]...
```

* 快照类型：0=完整快照，1=增量快照

* 基础版本：增量快照基于的完整快照版本号

### 3.2 版本号管理

* 全局快照版本号：每次完整快照递增

* 表级快照版本号：记录上次快照时的全局版本号

* 记录版本号：每次修改递增，用于检测变化

### 3.3 增量快照保存逻辑

1. 遍历所有表
2. 对于每个表，遍历所有已使用的记录
3. 只保存版本号大于表快照版本的记录
4. 更新表快照版本号

### 3.4 增量快照恢复逻辑

1. 检查快照类型
2. 如果是完整快照，按照现有逻辑恢复
3. 如果是增量快照：

   * 验证基础版本号匹配

   * 只恢复版本号大于当前记录版本的记录

   * 合并新增、修改和删除的记录
