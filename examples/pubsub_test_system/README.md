# PubSub测试系统

## 1. 系统概述

PubSub测试系统是一个完整的发布-订阅测试框架，用于验证remdb的pubsub功能。该系统包含服务器端和客户端组件，支持WAL日志主题和表内容主题的发布与订阅，实现了心跳检测机制，并提供了全面的测试用例。

## 2. 注意事项

### 2.1 Windows环境限制

在Windows环境中，UDP端口只能被一个进程绑定。因此，服务器和客户端不能同时运行在同一个端口上。我们的测试系统使用了不同的端口配置来避免这个问题：

- 心跳机制测试：使用端口5555
- 发布-订阅基础流程测试：使用端口5556
- WAL日志主题专项测试：使用端口5557
- 表内容主题专项测试：使用端口5558

### 2.2 接收循环要求

PubSub系统需要一个接收循环来处理接收到的消息。目前，`receive_loop`方法是私有的，并且是一个阻塞的无限循环。在生产环境中，你需要在一个单独的线程中运行它。

## 5. 测试流程

### 5.1 心跳机制测试

**测试目的**：验证服务器与客户端之间的连接保持、超时检测和自动重连功能

**测试流程**：
1. 启动服务器
2. 启动客户端
3. 客户端订阅心跳主题
4. 服务器定期发送心跳
5. 客户端监控心跳接收情况
6. 检查连接状态是否正确更新
7. 测试连接断开后的重连逻辑

### 5.2 发布-订阅基础流程测试

**测试目的**：验证消息从发布到接收的完整路径

**测试流程**：
1. 启动服务器
2. 启动客户端
3. 客户端订阅指定主题
4. 客户端发布测试消息到同一主题
5. 检查是否收到发布的消息
6. 验证消息内容的完整性

### 5.3 WAL日志主题专项测试

**测试目的**：验证WAL日志主题的消息格式、发布频率和订阅可靠性

**测试流程**：
1. 启动服务器（配置WAL日志发布频率）
2. 启动客户端
3. 客户端订阅WAL日志主题
4. 等待接收多个WAL日志消息
5. 验证消息格式的正确性
6. 验证消息发布频率是否符合配置
7. 验证消息接收的可靠性

### 5.4 表内容主题专项测试

**测试目的**：验证表数据变更消息的准确性、完整性和实时性

**测试流程**：
1. 启动服务器（配置表内容发布频率）
2. 启动客户端
3. 客户端订阅表内容主题
4. 等待接收多个表内容消息
5. 验证消息格式的准确性

## 6. 配置参数

### 6.1 服务器配置

| 参数名称 | 默认值 | 描述 |
|---------|-------|------|
| udp_port | 5555 | UDP监听端口 |
| max_topics | 32 | 最大主题数 |
| max_subscribers_per_topic | 16 | 每个主题最大订阅者数 |
| buffer_size | 4096 | 缓冲区大小（字节） |
| enable_nack | true | 是否启用NACK机制 |
| retransmit_timeout_ms | 100 | 重传超时时间（毫秒） |
| max_retransmits | 3 | 最大重传次数 |
| heartbeat_interval_secs | 5 | 心跳发送间隔（秒） |
| wal_publish_interval_ms | 1000 | WAL日志发布间隔（毫秒） |
| table_content_publish_interval_ms | 2000 | 表内容发布间隔（毫秒） |

### 6.2 客户端配置

| 参数名称 | 默认值 | 描述 |
|---------|-------|------|
| udp_port | 5555 | UDP端口 |
| buffer_size | 4096 | 缓冲区大小（字节） |
| heartbeat_timeout_secs | 15 | 心跳超时时间（秒） |

### 6.3 测试配置

| 参数名称 | 默认值 | 描述 |
|---------|-------|------|
| heartbeat_test_duration_secs | 10 | 心跳测试时长（秒） |
| basic_flow_test_duration_secs | 5 | 基础流程测试时长（秒） |
| wal_log_test_duration_secs | 5 | WAL日志测试时长（秒） |
| table_content_test_duration_secs | 6 | 表内容测试时长（秒） |
| test_message_size | 64 | 测试消息大小（字节） |
| message_send_interval_ms | 500 | 消息发送间隔（毫秒） |
| num_connections | 1 | 连接数 |

## 9. 注意事项

1. **Windows环境限制**：在Windows上，UDP端口只能被一个进程绑定，因此服务器和客户端不能同时运行在同一个端口上。

2. **接收循环要求**：PubSub系统需要一个接收循环来处理接收到的消息。目前，`receive_loop`方法是私有的，并且是一个阻塞的无限循环。

3. **测试环境**：测试系统需要在一个支持UDP广播的网络环境中运行。

4. **防火墙设置**：确保防火墙允许UDP端口的通信。

5. **性能测试**：在进行性能测试时，建议调整缓冲区大小、发送频率等参数，以获得更准确的测试结果。

## 10. 故障排除

### 10.1 无法接收消息

- 检查服务器和客户端是否使用了相同的UDP端口
- 检查接收循环是否正常运行
- 检查防火墙设置
- 检查网络环境是否支持UDP广播

### 10.2 连接断开

- 检查心跳超时设置
- 检查服务器是否正常运行
- 检查网络连接是否稳定

### 10.3 性能问题

- 调整缓冲区大小
- 调整发送频率
- 减少连接数
- 优化消息处理逻辑
